# Feature Specification: 写真型バケットリスト

**Feature Branch**: `001-photo-bucket-list`

**Created**: 2026-09-22

**Status**: Draft

**Input**: User description: "写真型のバケットリスト(5 x 5などのマス目を用意してそこにやりたいこと、いきたいとこ、たべたいとこなどの情報を入力しておき、達成した際の写真を貼れるようにし最終的に一枚の写真として保存できるようにしたい）、をPWAで実現したい。公開場所はgithub pages の予定です。"

## Clarifications

### Session 2026-09-22

- Q: 3×4・4×3 を選んだとき、ボードと保存画像はどんな形にするか？ → A: マスは正方形のまま。3×4 は横3列×縦4行の縦長 3:4、4×3 は横4列×縦3行の横長 4:3 のボード・保存画像とする
- Q: 保存画像にタイトルを入れるとき、画像全体の縦横比をどう保つか？ → A: 保存するときにタイトルの有無を切り替えられる。入れる場合はマス目の上に重ねて表示し、画像は有無にかかわらずマス目だけで正確に 1:1・3:4・4:3 とする

## User Scenarios & Testing *(mandatory)*

### User Story 1 - マス目にやりたいことを書き込む (Priority: P1)

ユーザーはマス目の大きさ（例: 5×5）を選んで新しいバケットリストを作ります。各マスに「やりたいこと」
「行きたいところ」「食べたいもの」などを書き込み、あとで見返したり書き直したりできます。
アプリを閉じて開き直しても内容は残っています。

**Why this priority**: 目標を書き込んだマス目がなければ、写真を貼ることも画像を保存することもできません。
これだけでも「やりたいことを一覧できるボード」として使えます。

**Independent Test**: 5×5 のボードを作って数マスに項目を書き込み、アプリを再起動しても同じ内容が
表示されることを確かめます。

**Acceptance Scenarios**:

1. **Given** ボードが1つもない状態, **When** マス目サイズに 5×5 を選んでボードを作る, **Then** 空のマスが 25 個並んだボードが表示される
2. **Given** ボードが1つもない状態, **When** マス目サイズに 3×4 を選んでボードを作る, **Then** 横3列×縦4行で、全体が縦長 3:4 のボードが表示される
3. **Given** 空のマス, **When** マスをタップして「京都で抹茶パフェを食べる」と入力し、カテゴリに「食べたい」を選んで保存する, **Then** そのマスにタイトルとカテゴリが表示される
4. **Given** 項目の入ったマス, **When** 内容を編集または削除する, **Then** 変更がすぐにボードへ反映される
5. **Given** 項目を入力したボード, **When** アプリを閉じて開き直す, **Then** 入力した内容がすべて残っている

---

### User Story 2 - 達成したマスに写真を貼る (Priority: P1)

やりたいことを達成したら、ユーザーはそのマスを開いてカメラで撮影するか、端末の写真ライブラリから選んで
写真を貼ります。写真を貼ったマスは達成済みとして表示され、ボード全体で進み具合（例: 7/25 達成）が
わかります。

**Why this priority**: 「達成の証を写真で残す」ことがこのアプリの中心となる価値です。

**Independent Test**: 項目の入ったマスに写真を貼り、そのマスが写真付きの達成済み表示に変わり、
達成数が増えることを確かめます。

**Acceptance Scenarios**:

1. **Given** 項目の入った未達成のマス, **When** 写真ライブラリから写真を選んで貼る, **Then** マスに写真が表示され、達成済みになる
2. **Given** 項目の入った未達成のマス, **When** その場でカメラで撮影して貼る, **Then** 撮影した写真がマスに表示される
3. **Given** 写真を貼ったマス, **When** マス内の写真の表示範囲（どこを切り抜くか）を調整する, **Then** 調整した範囲でマスに表示される
4. **Given** 写真を貼ったマス, **When** 写真を差し替えるか外す, **Then** 差し替えた写真が表示される、または写真を外したマスが未達成に戻る
5. **Given** 通信のない場所, **When** 写真を貼る, **Then** 通信のあるときと同じように貼れて保存される

---

### User Story 3 - ボードを一枚の画像として保存・共有する (Priority: P2)

ユーザーはボード全体（各マスの項目、貼った写真、達成状態。タイトルを入れるかは選べる）を一枚の画像として端末に保存したり、
SNS などに共有したりできます。

**Why this priority**: 最終的な成果物として形に残し、人に見せることが目的の一つです。ただしボードを作って
写真を貼る部分（P1）ができていることが前提です。

**Independent Test**: いくつかのマスに写真を貼ったボードを画像として保存し、保存された画像が画面上の
ボードと同じ配置・内容になっていることを確かめます。

**Acceptance Scenarios**:

1. **Given** 写真が一部貼られたボード, **When** 「画像として保存」を選ぶ, **Then** ボード全体が一枚の画像として端末に保存される
2. **Given** 保存した画像, **When** 画面上のボードと見比べる, **Then** マスの並び、項目の文字、写真の切り抜き範囲、達成状態の表示が一致している
3. **Given** 位置情報を含む写真を貼ったボード, **When** 画像として保存する, **Then** 保存された画像に撮影場所などの位置情報が含まれていない
4. **Given** 共有機能に対応した端末, **When** 「共有」を選ぶ, **Then** 端末の共有メニューから画像を他のアプリへ送れる
5. **Given** 未達成のマスがあるボード, **When** 画像として保存する, **Then** 未達成のマスは項目の文字だけで表示される
6. **Given** 3×4 のボード, **When** タイトルを「入れる」にして画像を保存する, **Then** タイトルがマス目の上に重なった、縦 3:4 ちょうどの画像が保存される
7. **Given** 3×4 のボード, **When** タイトルを「入れない」にして画像を保存する, **Then** マス目だけの、縦 3:4 ちょうどの画像が保存される

---

### User Story 4 - ホーム画面に追加してアプリとして使う (Priority: P2)

ユーザーはこのアプリをスマホのホーム画面に追加し、普通のアプリのように起動できます。一度開いたあとは、
通信がなくてもすべての機能を使えます。

**Why this priority**: 旅先や飲食店など、通信が不安定な場所でその場で写真を貼る使い方が中心となるためです。

**Independent Test**: ホーム画面に追加し、機内モードで起動して、項目の編集・写真の貼り付け・画像保存が
できることを確かめます。

**Acceptance Scenarios**:

1. **Given** 対応ブラウザでアプリを開いた状態, **When** ホーム画面に追加する, **Then** ホーム画面のアイコンからブラウザの枠なしで起動できる
2. **Given** 一度アプリを開いたことがある端末, **When** 機内モードで起動する, **Then** ボードの閲覧・編集・写真の貼り付け・画像保存がすべてできる
3. **Given** 新しいバージョンのアプリが公開された, **When** ユーザーが次にアプリを開く, **Then** 保存済みのボードと写真を失わずに新しいバージョンになる

---

### User Story 5 - 複数のボードを持つ・バックアップする (Priority: P3)

ユーザーは「2026年にやりたいこと」「北海道旅行」のように複数のボードを作って切り替えられます。
また、ボードのデータ（項目と写真）をファイルに書き出しておき、機種変更のときや消えてしまったときに
読み込んで元に戻せます。

**Why this priority**: 長く使うほど重要になる機能ですが、はじめの価値を届けるためには必須ではありません。

**Independent Test**: ボードを2つ作って切り替えられることを確かめます。ボードを書き出したあとアプリの
データを消去し、書き出したファイルを読み込んで元どおりになることを確かめます。

**Acceptance Scenarios**:

1. **Given** ボードが1つある状態, **When** 新しいボードを作る, **Then** 一覧から2つのボードを切り替えて開ける
2. **Given** 写真付きのボード, **When** バックアップファイルに書き出す, **Then** 項目と写真をすべて含むファイルが端末に保存される
3. **Given** データが消えた状態, **When** バックアップファイルを読み込む, **Then** 書き出したときと同じボード（項目・写真・切り抜き範囲・達成状態）が戻る
4. **Given** 不要になったボード, **When** 確認のうえ削除する, **Then** そのボードと写真が端末から消える

---

### Edge Cases

- 項目を書いたあとでマス目のサイズを小さくする（5×5 → 3×3）と、はみ出る項目はどうなるか
  → 縮小すると項目が消えることを警告し、ユーザーが確認した場合だけ縮小する。
- 非常に大きな写真（例: 5000万画素）や縦長・横長の写真を貼った場合 → 表示・保存に使える大きさへ
  自動で縮小し、マスの形に合わせて切り抜く（初期状態は中央）。
- 画像以外のファイルや、読み込めない写真を選んだ場合 → わかりやすいエラーを表示し、マスは元のままにする。
- 端末の保存容量が足りない場合 → 保存できなかったことをユーザーに知らせ、それまでのデータは壊さない。
- 長い項目名（例: 60文字）→ 画面でも保存画像でも、マスからはみ出さないよう折り返すか省略して表示する。
- 空のマスが残っているボードを画像保存する → 空のマスは空白として表示する。
- 形式が違う、または壊れたバックアップファイルを読み込んだ場合 → 読み込みを中止し、既存のデータは変更しない。
- ブラウザのデータ消去でデータが消える可能性 → バックアップの書き出しを促す案内を表示する。

## Requirements *(mandatory)*

### Functional Requirements

**ボードとマス**

- **FR-001**: ユーザーは、マス目のサイズを 3×3、4×4、5×5、3×4（横3列×縦4行・縦長）、4×3（横4列×縦3行・横長）から選んでボードを作成できなければならない。マスはどのサイズでも正方形とし、3×4 のボードは縦 3:4、4×3 のボードは横 4:3 の縦横比になる
- **FR-002**: ユーザーは、ボードのタイトル（例: 「2026年やりたいこと」）を設定・変更できなければならない
- **FR-003**: ユーザーは、各マスに項目のタイトル（必須）、カテゴリ、任意のメモを入力・編集・削除できなければならない
- **FR-004**: カテゴリとして少なくとも「やりたい」「行きたい」「食べたい」「その他」を選べなければならず、マス上でカテゴリが見分けられなければならない
- **FR-005**: ユーザーは、マス同士の位置を入れ替えられなければならない
- **FR-006**: 作成後にマス目サイズを FR-001 の選択肢の中で変更でき、変更で範囲外になる行または列の項目が失われる場合は事前に警告して確認を求めなければならない

**写真と達成**

- **FR-007**: ユーザーは、項目の入ったマスに、端末のカメラで撮影した写真、または写真ライブラリから選んだ写真を1枚貼れなければならない
- **FR-008**: 写真を貼ったマスは達成済みとみなし、未達成のマスと見た目で区別できなければならない
- **FR-009**: ユーザーは、マス内での写真の表示範囲（位置と拡大率）を調整できなければならない
- **FR-010**: ユーザーは、貼った写真を差し替えたり外したりできなければならない。外すとそのマスは未達成に戻る
- **FR-011**: 写真を貼った日を達成日として記録し、マスの詳細で確認できなければならない
- **FR-012**: ボード全体の達成数と総マス数（例: 7/25）を表示しなければならない

**画像出力**

- **FR-013**: ユーザーは、ボード全体（全マスの項目・写真・達成状態）を一枚の画像として端末に保存できなければならない。保存画像の縦横比は、タイトルの有無にかかわらず、ボードの縦横比（1:1・縦 3:4・横 4:3）と正確に一致しなければならない
- **FR-013a**: ユーザーは、保存するときにボードのタイトルを画像に入れるかどうかを切り替えられなければならない。入れる場合、タイトルはマス目の上に重ねて表示し、背景の写真に関係なく読める見た目でなければならない。初期状態は「入れる」とし、前回の選択を記憶する
- **FR-014**: 保存画像の配置、文字、写真の切り抜き範囲は、画面上のボード表示と一致しなければならない
- **FR-015**: 保存画像には、元写真の撮影場所などのメタデータを含めてはならない
- **FR-016**: 保存画像は SNS 投稿や印刷に耐える解像度（長辺 2000px 以上）でなければならない
- **FR-017**: 端末が対応している場合、端末の共有メニューで画像を共有できなければならない

**保存・オフライン・インストール**

- **FR-018**: ボード、項目、写真はすべて利用者の端末内にだけ保存し、外部へ送信してはならない
- **FR-019**: 変更は自動で保存され、アプリを閉じて開き直しても内容が失われてはならない
- **FR-020**: 一度読み込んだあとは、通信がなくても全機能が使えなければならない
- **FR-021**: ホーム画面に追加して、単独のアプリとして起動できなければならない
- **FR-022**: アプリを更新しても、保存済みのデータは保持されなければならない

**複数ボードとバックアップ**

- **FR-023**: ユーザーは、複数のボードを作成し、一覧から切り替え、確認のうえ削除できなければならない
- **FR-024**: ユーザーは、ボード（項目と写真を含む）をバックアップファイルに書き出し、あとで読み込んで復元できなければならない
- **FR-025**: 不正なバックアップファイルを読み込んだ場合は、既存のデータを変更せずにエラーを表示しなければならない

**使いやすさ**

- **FR-026**: スマートフォンの縦画面で、横スクロールせずにボード全体（5×5・3×4・4×3 を含む）を見渡せなければならない
- **FR-027**: 画面表示は日本語でなければならない

### Key Entities

- **ボード**: 1つのバケットリスト。タイトル、マス目サイズ（行数・列数）、作成日、更新日を持ち、複数のマスを含む
- **マス（項目）**: ボード内の1つの位置にあるやりたいこと。位置、タイトル、カテゴリ、メモ、達成状態、達成日を持ち、写真を0枚または1枚持つ
- **写真**: マスに貼った達成の証。画像データと、マス内での表示範囲（位置・拡大率）を持つ
- **バックアップ**: 1つ以上のボードと、その項目・写真をまとめたファイル。形式のバージョンを持つ

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 初めて使う人が、アプリを開いてから 5×5 のボードを作り、最初の項目を入力するまでを 1 分以内に終えられる
- **SC-002**: 項目の入ったマスに写真を貼って達成済みにするまでを、3 回以下の操作（タップ）で 30 秒以内に終えられる
- **SC-003**: 25 マスすべてに写真を貼ったボードを、5 秒以内に一枚の画像として保存できる
- **SC-004**: 保存した画像と画面上のボードを見比べたとき、マスの並び・文字・写真の切り抜き範囲がすべて一致している（テスト用ボード10件で 100%）
- **SC-005**: 機内モードで、ボードの編集・写真の貼り付け・画像保存がすべて成功する
- **SC-006**: 25 枚の写真を貼ったボードが 3 つあっても、ボードを開いてから表示されるまで 2 秒以内に収まる
- **SC-007**: バックアップの書き出しと読み込みを行ったとき、項目・写真・切り抜き範囲・達成状態が 100% 元どおりになる
- **SC-008**: 試用した人の 8 割以上が、説明なしで「写真を貼る」「画像を保存する」を実行できる

## Assumptions

- 利用者は個人で、アカウント登録、ログイン、他人との共同編集は範囲外とする
- 端末間の自動同期は範囲外とし、端末を移るときはバックアップファイルで対応する
- 1マスに貼れる写真は1枚とする。写真を貼ったことをもって「達成」とし、写真なしで達成済みにする操作はv1では提供しない
- マス目サイズは 3×3・4×4・5×5・3×4・4×3 の5種類とする。マスは常に正方形とし、マス自体を長方形にすることや 6×6 以上は範囲外とする
- 保存画像はマス目部分だけで構成し、縦横比はボードの縦横比（正方形・縦 3:4・横 4:3）と一致させる。タイトルは切り替え可能で、入れる場合はマス目に重ねる（FR-013a）。デザインテーマの選択はv1では範囲外とする
- 対応環境は、最新の iOS Safari、Android Chrome、デスクトップの主要ブラウザとする
- アプリは静的なウェブサイトとして GitHub Pages で公開する（プロジェクト憲章 原則 II）
- 写真は端末内への保存容量を節約するため、見た目を損なわない範囲で縮小して保存する
