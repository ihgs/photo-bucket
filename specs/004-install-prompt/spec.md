# Feature Specification: ホーム画面への追加を促す案内

**Feature Branch**: `004-install-prompt`

**Created**: 2026-10-03

**Status**: Draft

**Input**: User description: "ブラウザで開いているときに、ホーム画面へのアプリ追加を促す"

## Clarifications

### Session 2026-10-03

- Q: 案内をいつ出すか？ → A: 初めて開いたときからすぐ（ボードがなくても出す）。まだデータがないうちに追加してもらえば、iPhone でデータの引き継ぎが要らない
- Q: 案内をどこに、どんな形で出すか？ → A: ボード一覧の上部に帯で出す（ボードがないときは使い方の案内の上）。ボードの編集中など、ほかの画面には出さない
- Q: 案内を閉じた人に、また出すか？ → A: 閉じてから 30 日後にもう一度だけ出す。それも閉じたら二度と出さない
- Q: ブラウザで作ったデータは、ホーム画面に追加したアプリに引き継がれるか？ → A: Android・パソコンの Chrome・Edge では引き継がれる（同じ保存場所）。iPhone・iPad（と Mac の Safari）では引き継がれない（ホーム画面のアプリは別の保存場所で、空から始まる）
- Q: iPhone で、ブラウザにすでにボードがあるとき、引き継がれないことを案内するか？ → A: 案内する。「先にバックアップを書き出し、追加したアプリで読み込んでください」と添える

## 背景

このアプリはホーム画面に追加すると、普通のアプリのように起動でき、通信のない場所でも使える（001 FR-020・FR-021）。
しかしブラウザで開いたままだと、ユーザーは追加できることに気づきにくい。また、ブラウザのデータは、ホーム画面に追加したアプリより
消されやすい端末がある（写真が端末の中にしかないこのアプリでは重要）。そこで、ブラウザで開いているときに、ホーム画面への追加を案内する。

端末によってできることが違う（実現性の調査結果）:

- **ボタン1つで追加できる端末**（Android の Chrome、パソコンの Chrome・Edge）: 案内の「アプリとして追加」を押すと、ブラウザの追加画面が開く
- **手順の案内しかできない端末**（iPhone・iPad のブラウザ、Mac の Safari）: アプリから追加画面を開く方法がないため、ブラウザのメニューからの手順を示す
- **追加できない場所**（LINE・Instagram などのアプリ内ブラウザ）: 普通のブラウザで開き直すよう案内する

## User Scenarios & Testing *(mandatory)*

### User Story 1 - ボタン1つでホーム画面に追加する (Priority: P1)

Android の Chrome でアプリを開いているユーザーに、ボード一覧の上部に、ホーム画面への追加の案内が帯で表示されます（初めて開いたときから）。
「アプリとして追加」を押すとブラウザの追加画面が開き、追加するとホーム画面にアイコンができます。追加したあとは、ブラウザで開いても案内は出ません。

**Why this priority**: 追加までの手間が一番少なく、効果が大きい。Android とパソコンの Chrome・Edge で使える。

**Independent Test**: Android の Chrome で案内が出る条件を満たし、「アプリとして追加」→ ブラウザの追加画面で「インストール」を押して、
ホーム画面にアイコンができ、案内が消えることを確かめます。

**Acceptance Scenarios**:

1. **Given** ボタン1つで追加できる端末のブラウザで、案内を出す条件を満たした状態, **When** 画面を開く, **Then** 「ホーム画面に追加すると、アプリのように使えます」という案内と「アプリとして追加」ボタンが表示される
2. **Given** 案内が表示されている, **When** 「アプリとして追加」を押す, **Then** ブラウザの追加画面が開く
3. **Given** ブラウザの追加画面, **When** 追加する, **Then** 案内が消え、以後このブラウザでは表示されない
4. **Given** ブラウザの追加画面, **When** キャンセルする, **Then** 案内は「閉じた」ときと同じ扱いになる（FR-007）
5. **Given** ホーム画面のアイコンから起動したアプリ, **When** どの画面を開いても, **Then** 案内は表示されない

---

### User Story 2 - iPhone・iPad で追加の手順を知る (Priority: P1)

iPhone の Safari でアプリを開いているユーザーには、同じ場所に、ホーム画面への追加の手順（「共有ボタン → ホーム画面に追加」）が、
共有ボタンのアイコン入りで表示されます。ユーザーはそれを見ながら自分で追加できます。
iPhone では、ブラウザで作ったデータは追加したアプリに引き継がれません。そのため、ブラウザにすでにボードがある場合は、
「先にバックアップを書き出し、追加したアプリで読み込んでください」という注意と、書き出すボタンも案内に表示されます。

**Why this priority**: このアプリの主な利用者はスマートフォンで、iPhone の利用者が多い。iPhone ではボタン1つで追加できないため、手順を示すしかない。

**Independent Test**: iPhone の Safari で案内が出る条件を満たし、手順の案内が表示されること、その手順どおりにホーム画面に追加できることを確かめます。

**Acceptance Scenarios**:

1. **Given** iPhone・iPad の Safari で、案内を出す条件を満たした状態, **When** 画面を開く, **Then** 「共有ボタン（アイコン）をタップ → 『ホーム画面に追加』を選ぶ」という手順の案内が表示される
2. **Given** iPhone・iPad の Safari 以外のブラウザ（Chrome など）, **When** 案内を出す条件を満たす, **Then** そのブラウザでの共有ボタンの場所に合わせた手順が表示される
3. **Given** Mac の Safari, **When** 案内を出す条件を満たす, **Then** 「メニューの『ファイル』→『Dock に追加』」という手順が表示される
4. **Given** 手順の案内, **When** 「閉じる」を押す, **Then** 案内が消える（FR-007）
5. **Given** iPhone の Safari でボードが1つ以上ある状態, **When** 案内が表示される, **Then** 「ホーム画面に追加したアプリには、ここで作ったボードは引き継がれません。先にバックアップを書き出し、追加したアプリで読み込んでください」という注意と、バックアップを書き出す画面へのボタンが表示される
6. **Given** iPhone の Safari でボードが1つもない状態, **When** 案内が表示される, **Then** データの引き継ぎの注意は表示されない

---

### User Story 3 - アプリ内ブラウザでは普通のブラウザで開き直すよう案内する (Priority: P2)

LINE などで共有されたリンクからアプリを開いたユーザーには、「ホーム画面に追加するには、Safari（Android では Chrome）で開いてください」と表示されます。
アプリ内ブラウザではホーム画面に追加できず、ブラウザのデータも消えやすいためです。

**Why this priority**: 共有されたリンクから初めて開く人は多いが、そのまま使うと保存したデータが失われやすい。ただし iPhone・Android の通常のブラウザ（P1）より利用は少ない。

**Independent Test**: LINE のアプリ内ブラウザでアプリを開き、開き直しの案内が表示されることを確かめます。

**Acceptance Scenarios**:

1. **Given** アプリ内ブラウザで、案内を出す条件を満たした状態, **When** 画面を開く, **Then** 「ホーム画面に追加するには、Safari（Android では Chrome）で開いてください」と、そのアプリのメニューから開き直す方法が表示される
2. **Given** アプリ内ブラウザの案内, **When** 「閉じる」を押す, **Then** 案内が消える（FR-007）

---

### Edge Cases

- ホーム画面に追加済みだが、ユーザーがブラウザでも開いた場合 → ボタン1つで追加できる端末では、ブラウザが「追加できる」と知らせてこないので案内を出さない。iPhone では追加済みかどうかを判定できないため、閉じた記録（FR-007）に従って表示する（一度閉じれば出ない）
- 案内を出す条件を満たしていても、ボタン1つで追加できる端末でブラウザが「追加できる」と知らせてこない場合（すでに追加済み、ブラウザの判断で見送り など）→ 案内を出さない
- ブラウザの種類を判定できない場合 → 案内を出さない（誤った手順を示さない）
- 対象外のブラウザ（Firefox）→ 案内を出さない
- オフラインのとき → 案内は出してよい（追加は通信がなくても完了する端末が多い。追加できなかった場合はブラウザが知らせる）
- ブラウザのデータを消した場合 → 閉じた記録も消えるため、条件を満たせば再び案内が出る
- 案内がボード画面の下部などの操作を隠さないか → 案内は操作ボタンを隠してはならない（FR-009）
- ボードが1つもないときの使い方の案内（001 FR-028）と同時に出るか → 出る。追加の案内を上、使い方の案内をその下に並べる
- Android の Chrome などで、ブラウザでボードを作ってから追加した場合 → データは同じ保存場所なのでそのまま使える。引き継ぎの注意は出さない
- 起動時に最後に開いたボードを開く動き（001）で、ボード一覧を通らなかった場合 → そのときは案内を出さない。ボード一覧に戻ったときに出す

## Requirements *(mandatory)*

### Functional Requirements

**案内を出すかどうか**

- **FR-001**: 案内は、アプリをブラウザで開いているときだけ表示しなければならない。ホーム画面のアイコンから起動したアプリ（単独のアプリとして表示されているとき）では表示してはならない
- **FR-002**: 案内は、初めて開いたときから表示しなければならない（ボードの有無にかかわらない）。ただし、閉じた記録があるときは FR-007 に従う
- **FR-003**: 案内は、ボード一覧の画面の上部に帯で表示しなければならない。ボードがないときは、使い方の案内（001 FR-028）の上に表示する。ボード一覧以外の画面には表示してはならない
- **FR-004**: ブラウザの種類が判定できない、または対象外のブラウザ（Firefox）の場合は、案内を表示してはならない

**端末ごとの内容**

- **FR-005**: ボタン1つで追加できる端末では、案内に「アプリとして追加」ボタンを置き、押したらブラウザの追加画面を開かなければならない。ブラウザが「追加できる」と知らせてきていないときは、案内を表示してはならない
- **FR-006**: 手順の案内しかできない端末では、そのブラウザでの追加の手順を表示しなければならない。iPhone・iPad では共有ボタンのアイコンを手順の中に示し、Mac の Safari では「ファイル」→「Dock に追加」を示す。アプリ内ブラウザでは、普通のブラウザ（iPhone・iPad では Safari、Android では Chrome）で開き直すよう案内する

**閉じる・追加した後**

- **FR-007**: どの案内にも「閉じる」ボタンを置かなければならない。閉じた場合、またはボタン1つで追加できる端末で追加画面をキャンセルした場合は、その端末のそのブラウザで、閉じてから 30 日間は表示してはならない。30 日たったら一度だけ再び表示し、それも閉じた（またはキャンセルした）場合は、以後表示してはならない
- **FR-008**: ホーム画面に追加されたことがわかった場合（ボタン1つで追加できる端末）は、案内を消し、以後そのブラウザでは表示してはならない

**見た目と操作**

- **FR-009**: 案内は、マスやボタンなどの操作を隠してはならない。また、新しいバージョンのお知らせ（001 FR-022）と同時に表示されるときも、両方が読めて操作できなければならない
- **FR-010**: 案内は、スクリーンリーダーで内容とボタンが読み上げられ、キーボードでも操作できなければならない。ボタンのタップ領域は 44px 以上とする
- **FR-011**: 案内を表示・閉じる・追加するために、外部と通信してはならない（憲章 I）。閉じた記録は端末の中にだけ保存する

**データの引き継ぎ**

- **FR-012**: ホーム画面に追加したアプリにデータが引き継がれない端末（iPhone・iPad、Mac の Safari）で、ブラウザにボードが1つ以上あるときは、案内に「ホーム画面に追加したアプリには、ここで作ったボードは引き継がれません。先にバックアップを書き出し、追加したアプリで読み込んでください」という注意と、バックアップを書き出す画面（003 の `#/backup`）を開くボタンを表示しなければならない。ボードが1つもないとき、およびデータが引き継がれる端末では、この注意を表示してはならない

### Key Entities *(include if feature involves data)*

- **案内の記録**: 端末（ブラウザ）ごとに、案内を閉じた回数（0・1・2）と最後に閉じた日時、ホーム画面に追加されたかどうかを持つ。ボードのデータやバックアップファイルには含めない

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: ホーム画面のアイコンから起動したアプリで、案内が表示される回数が 0 回
- **SC-002**: ボタン1つで追加できる端末で、案内からホーム画面に追加するまでの操作が 2 タップ以内（「アプリとして追加」とブラウザの追加画面での確定）
- **SC-003**: iPhone・iPad で、案内の手順だけを見て、初めての人の 9 割以上がホーム画面に追加できる
- **SC-004**: 案内を閉じたユーザーに、30 日たつまで再び案内が表示される回数が 0 回。2 回閉じたユーザーに再び表示される回数が 0 回
- **SC-005**: 案内が表示されているときも、ボード一覧・ボード画面のすべての操作ができる（隠れるボタンが 0 個）
- **SC-006**: iPhone でブラウザにボードがあるユーザーが、案内に従って追加したアプリに、バックアップでボードをすべて移せる（移せなかったボードが 0 個）

## Assumptions

- ホーム画面に追加できる条件（アプリの情報ファイル、オフライン用の仕組み、HTTPS での配信）は、001 ですでに満たしている
- 対象のブラウザは 001 と同じ（最新の iOS Safari、Android Chrome、デスクトップの Chrome・Edge・Safari）。Firefox は対象外
- iPhone・iPad では、ホーム画面に追加済みかどうかをブラウザ側から判定できない。そのため閉じた記録だけで出し分ける
- iPhone・iPad では、ホーム画面に追加したアプリと Safari は別の保存場所を持つ（データは引き継がれない）。Mac の Safari の「Dock に追加」も同様と想定し、実機で確かめる。Android・パソコンの Chrome・Edge では同じ保存場所を使う
- 案内の文言は日本語だけとする（憲章の技術的制約）
- 案内の表示回数や追加率の集計（アクセス解析）は行わない（憲章 I）。SC-003 は手作業の利用者テストで確かめる
- アプリ内ブラウザの判定は、主なもの（LINE、Instagram、Facebook、X）を対象とし、それ以外は通常のブラウザとして扱う
